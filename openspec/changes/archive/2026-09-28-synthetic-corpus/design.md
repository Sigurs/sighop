# Design

## Context

See `proposal.md` for why. What the recorded corpus is, as measured:

- 13 `captures/*.jsonl` files, 1,232 frame records; the protocol harness reads 8 of them (1,093 frames,
  35 transmitted), and the rest are read only by the channel tests and the live-pipeline replay, which
  glob `captures/*.jsonl`.
- Every consumer goes through one constant, `CAPTURES_DIR` in `tests/protocol/corpus.py`, or names a file
  directly. About 25 test modules use it. Most only want "a realistic stream of receptions": they take
  `CAPTURE_FILES[0]` or `2026-09-04-03.jsonl` and assert on the pipeline's behaviour, not on the frames.
- A minority pin facts about the recording: the distribution constants and per-file counts in
  `corpus.py` / `test_corpus.py`, the 85 / 108 Public / other-channel split, the golden file, and
  literals copied out of it (real node names and key prefixes in `test_payloads.py` and
  `test_adverts.py`, real key prefixes in `CORPUS.md`, `DESIGN.md` and a few archived change documents).
- `build.sh` replays every `captures/*.jsonl` on the host and inside the image and compares them byte
  for byte; `tests/test_deployment_files.py` asserts that shape. `.dockerignore` already keeps
  `captures/` out of the image and `keys/` is gitignored; the corpus is the exception.
- The codec already has an encoder for every payload the corpus holds (`encode`, `build_advert`,
  `build_direct_envelope`, `build_group_envelope`, `build_ack`, `build_discover_*`,
  `build_returned_path_body`, `build_room_login_body`, `sign_advert`, `encrypt_then_mac`,
  `LocalIdentity.from_seed`, `channel_key_from_hashtag`). Nothing new is needed under `src/`.

## Goals / Non-Goals

**Goals:**

- A corpus with no real identity, name, message or private key, whose absence of them is checked rather
  than promised.
- Every existing consumer keeps working through the same replay path; the change is confined to what
  the files contain and where they live.
- The corpus is smaller and less repetitive without losing a shape it held.

**Non-Goals:**

- Purging hosts, forks or clones other than this repository, and the CCE index and Claude transcripts
  (D12) — reported, not touched.
- Generating traffic for load testing, or fuzzing. The corpus is a fixed regression set.
- Restoring the withdrawn interoperability evidence with a fresh live capture. If wanted, that is its
  own change, and it must scrub before it commits.
- Changing the capture writer, the replay reader or anything in `src/`.

## Decisions

### D1. Committed generated files, not a generate-at-test-time fixture

The generator writes ordinary JSONL to `tests/corpus/`, the files are committed, and a test proves
they equal a fresh in-memory generation.

Alternative: generate into a session fixture (`tmp_path`) and never commit. Rejected: `build.sh`'s
replay gate and `python -m sighop.replay <file>` need real files on disk, the image comparison
mounts a directory, and a reviewable diff of corpus changes is the point of the golden file. The
drift test gives the reproducibility of generation with the ergonomics of files.

### D2. The corpus moves to `tests/corpus/`; `captures/` is gitignored

Synthetic data is a test fixture, not a capture, and leaving it in `captures/` would let a live
`SIGHOP_CAPTURE_FILE` recording and the fixture sit side by side and be committed together. All
consumers already import `CAPTURES_DIR`; renaming it to `CORPUS_DIR` (with the old name removed, not
aliased) turns a missed consumer into an import error rather than a silently empty replay.
`build.sh`, its bind mount and `test_deployment_files.py` follow.

### D3. Generator in `tests/protocol/synthetic.py`, one seed, one cast

- **Identities.** `LocalIdentity.from_seed(sha256(f"{SEED}:{role}:{n}"))`. The seed is a module constant
  with a `GENERATOR_VERSION`; both go in every `capture_meta`.
- **Cast.** A small declared table: roughly 12 repeaters, 3 room servers, 8 chat nodes, plus the two
  local identities that play "sighop" and "its peer" in the exchange file. Names carry a fixed
  fictional prefix (`syn-`), e.g. `syn-ridge-repeater`, so the guard can test membership and a reader
  cannot mistake one for real. Some names are longer than one hash-size boundary so the multi-byte
  discrimination in the spec has something to bite on.
- **Text.** A fixed list of fictional chat lines and sender names for the Public channel and for a
  second channel derived from a synthetic hashtag. No text is generated by a model at run time; it is
  written in the file.
- **Time and signal.** Timestamps from a fixed start advanced by a seeded schedule; SNR / RSSI drawn
  from `random.Random(SEED)` per file so adding a frame to one file does not perturb another.
- **Records.** The generator builds bytes with the `src/sighop` encoders and emits the same dict shapes
  `CaptureWriter` writes (`rx_frame`, `tx_frame`, one `unparsed`, `capture_meta` header). A test reads
  each file through `CaptureReplay` to prove the shapes are the writer's.

The generator imports from `sighop` and lives in `tests/`, so it stays under the existing import-boundary
test (`test_import_boundary.py`) that keeps `src/` from importing tests.

Alternative: hand-write frames as hex. Rejected: unmaintainable, and it would freeze our misreadings
in bytes nobody can regenerate. Alternative: mutate the recording (rewrite names, re-sign). Rejected:
re-signing needs new keys anyway, and it keeps the recording's structure, timing and volume, which is
the quality problem.

### D4. Three files, each with a job

| File | Records | Job |
|---|---|---|
| `synthetic-ambient.jsonl` | ~200 rx | Receive-only mesh: adverts of every node type / flag form, flood and direct routing, hops 0-5, hash sizes 1-3, TRACE, PATH, discovery, one `TRANSPORT_FLOOD`, the flood repeats and the late echo |
| `synthetic-channels.jsonl` | ~70 rx | Public-channel group text and a second channel, both `0x11`/`0x17` discriminations, a few group-data frames |
| `synthetic-exchange.jsonl` | ~60 rx+tx | sighop identity and a synthetic peer: DMs both ways, both ACK forms, the retransmitted DM, room login / post / refusal / push / ack, a REQ and RESPONSE, and sighop's own adverts as `tx_frame` |

About 330 frames, against 1,093. `corpus.py` exposes them by role (`AMBIENT`, `CHANNELS`, `EXCHANGE`)
rather than by date, and tests that took "the first capture" or `2026-09-04-03.jsonl` take `AMBIENT`.
Which tests need which file is settled in the tasks by running them, not guessed here.

### D5. A repetition budget, and each repeat is named

The recorded corpus was ~34% repeats. The budget is: **at most 12% of receptions repeat a packet already
seen, at most 3 copies of any packet.** The generator has one function that emits a repeat and it takes a
`reason` string, so every duplicate in the output is traceable to a line that says why. The designed
repeats are:

- ordinary flood repeats over a different path, seconds apart (what `test_dedup` and path learning
  need),
- exactly one late echo over a different path at ~200 s (what shows a 60 s TTL is too short),
- exactly one identical DM retransmitted after >30 min (what shows the TTL must stay short enough not
  to swallow a sender's retry).

Everything else is unique by construction, and a test checks it.

### D6. Guard and drift tests

- **Drift:** regenerate in memory, compare bytes to the committed files.
- **No-real-data guard:** every advert's key and name, and every decrypted sender and text, must be in
  the cast; this is checked against the cast *table*, not a denylist of real names, so the guard needs no
  real data to exist in the repo. A separate test scans tracked files for private-key material
  (`private_key_hex` / `seed_hex` with a value) outside test code that builds keys in memory.
- **Manifest:** the generator can print counts; the recorded expectations in `corpus.py` /
  `test_corpus.py` are typed in from a reviewed run and never overwritten by tooling, as today.

### D7. The interoperability evidence is withdrawn, not faked

Per the decision to drop the first-transmit exchange, `test_foreign_decrypt.py`,
`burned-first-transmit.json` and the recorded Public-channel frames are removed. What replaces them is
labelled for what it is: a self-consistency test over generated frames (`mesh-crypto` delta). The
negative tests that made the old evidence falsifiable (wrong key slice, `0x17` vs `0x11`, another
channel stays closed) are kept over the synthetic frames because they test the code, not the
recording. Signing keeps its firmware-embedded keypair anchor and the `test_crypto.py` vectors, neither of
which touched the corpus. `CORPUS.md` and `DESIGN.md` record that the exchange existed and passed once.

### D8. Documentation moves with the data

`CORPUS.md` is rewritten around the generator: what the cast is, the file roles, the budget, what the
corpus proves and does not. Its recorded-mesh measurements (flood repeat rate, late echo, retransmit
gap) are findings about the real mesh that sized the dedup TTL; they carry no identity, so they move
verbatim into `DESIGN.md` as recorded history rather than being deleted, and `CORPUS.md` points there.
Real key prefixes and node names in `DESIGN.md`, `CORPUS.md` and archived change documents are replaced
with `[redacted]` or a cast name; the archive is otherwise left alone.

### D9. Finding what to scrub without committing it

The list of real names and key prefixes exists only in the recording. Task 1 extracts it from
`git show HEAD:captures/...` into the scratchpad, **before** the deletion, and the final task greps the
working tree against it. The list is never committed, since it would be the leak.

### D10. Purge with `git filter-repo` on a fresh clone

`git-filter-repo` is not installed; run it as `uvx git-filter-repo`, so nothing is added to the project.
Work in a fresh `git clone --no-local` of the repository (the tool's own safety check requires one),
with two passes in one invocation:

- `--invert-paths` for `captures/`, `tests/fixtures/burned-first-transmit.json` and `.env.prod`, which
  drops every revision of them on every branch. History today shows exactly these paths for the
  sensitive content (`captures/*`, the burned fixture, `.env.prod`); the inventory task re-runs the
  listing rather than trusting this.
- `--replace-text` with an expressions file built in task 1.1 (real node names and key prefixes, and the
  `.env.prod` values), replacing each literal with `[redacted]` in every blob. Names are literal, not
  regex, so a real name that is also a common word is reviewed before it goes on the list.

The expressions file and the backup bundle live outside the repository (scratchpad or `~`), because
the list is itself the leak. Redaction leaves old commits' tests inconsistent with their own data (a
frame whose key was redacted no longer verifies). That is accepted: only the tip has to build.

Alternatives: `git filter-branch` — deprecated, slow, and leaves refs behind. BFG — path and blob
oriented, weak at multi-string text redaction. Rewriting in place with `--force` — works, but discards
the tool's guard that the repository has no other state to lose; the fresh clone keeps the original
intact until swap.

### D11. Last, and gated

The purge runs after tasks 1-8 are committed, so the rewrite carries the finished change, and stops at a
confirmation before swapping. The steps are: bundle backup, rewrite on the clone, verify (no removed
path in `git log --all --name-only`, no listed string in `git grep` over `git rev-list --all`, both
branches present, tip tree equal to the pre-rewrite tip except for redactions), confirm with the
operator, replace the repository, then `git reflog expire --expire=now --all` and
`git gc --prune=now --aggressive`. The repository has no remote, so there is nothing to force-push;
if the operator adds one first, the rewritten history needs `--force-with-lease` and is theirs to run.

### D12. What git cannot fix

- **`.env.prod` secrets** (`SIGHOP_SECRET_KEY`, `DATABASE_URL`): removed from history but disclosed
  wherever the old history went; rotate them, which signs out web sessions and changes the database
  password. A task lists it; the operator performs it.
- **The burned key** needs no rotation: it was burned when it was published. `keys/` was never
  committed and is left alone.
- **Local copies outside git.** The CCE index and memory under `~/.cce` (bind-mounted into the dev
  container) index the captures and quote real names; clear and reindex after the purge. Claude
  session transcripts and tool-result files under `~/.claude/projects/` contain excerpts, including
  from the session that wrote this plan; the operator decides whether to delete them.
- **Other clones, forks, CI caches and hosting**: any copy of the old history must be re-cloned or purged
  by its owner. The change reports this; it cannot do it.

## Risks / Trade-offs

- **A generated corpus cannot surprise us** → the recording found the multi-byte path-hash misreading
  and a wrong ACK construction because it was someone else's implementation. The spec keeps the
  multi-byte discrimination, both ACK forms and the discovery forms as explicit cases, and
  `CORPUS.md` says plainly what is no longer proven. Interop stays anchored by the firmware keypair and
  known-answer vectors.
- **Tests that pinned recorded facts fail in bulk** → expected; they are re-derived from the manifest in
  small groups (task order below), not patched to pass.
- **A test quietly depends on a property of the recording** (for example "the first capture contains a
  DIRECT zero-hop advert") → the generator's file roles are chosen to keep each such property; a test
  that still fails is a finding to fix in the generator or the test, never a reason to loosen an
  assertion.
- **History rewrite is irreversible once pruned** → backup bundle first, rewrite on a fresh clone, verify,
  and swap only on the operator's confirmation (D10, D11).
- **Hashes change** → every commit on both branches; notes and CCE memory that cite a hash go stale.
  Accepted; the change lists where.
- **A large diff** → mostly deletions (23 files under `captures/`); the additions are three JSONL files,
  one generator and the tests that guard them.

## Migration Plan

1. Extract the real-name list (D9), then land the generator, cast and drift/guard tests beside the old
   corpus so both exist briefly.
2. Switch `corpus.py` and the protocol tests, then the ~25 consumers, to `tests/corpus/`.
3. Delete `captures/*`, the burned fixture and the old golden file; regenerate the golden file.
4. Move `build.sh` / deployment test / `.gitignore`, then scrub the documents and grep the tree.
5. Commit, then purge history (D10-D11) after the operator confirms; rotate secrets and clean the local
   copies (D12).

**At archive.** The delta specs replace requirements, but `openspec/specs/protocol-corpus/spec.md`
also carries a Purpose paragraph and a status blockquote ("The corpus stands at 997 frames across
six files…") that no requirement covers, and both still describe recorded files and counts. Update
them by hand in the same step as the sync: the corpus is 282 frames in three generated files under
`tests/corpus/`, provenance is a synthetic `capture_meta` header, and the Purpose is a generated
regression corpus and not "recorded live traffic". `openspec/specs/mesh-crypto/spec.md` has no such
paragraph; its removed requirements are covered by the delta.

Until step 5, rollback is `git revert`: the recorded files return with it. After the purge, rollback is
the backup bundle, which is the only remaining copy of the real data; the operator deletes it when
satisfied. There is no data migration and nothing under `src/` changes.
