# Design

## Context

- `WebhookEvent` is built synchronously in `WebhookDispatcher.on_observation` (contact-store
  listener, reception path) and carries `position: Position | None`. Renderers in
  `webhooks/render.py` are pure functions of the event; `discord_location()` and `maps_url()` shape
  the Location field and `node.position`.
- `WebhookDispatcher.run()` pops events off a bounded queue and fans out deliveries; retries reuse
  the same event object. `send_sample()` builds `sample_event()` (Stockholm position) and posts once.
- The project avoids new runtime dependencies (webhooks use stdlib `urllib`). The image is
  python:3.13-alpine with a read-only root; `uv_build` ships every file under `src/sighop/` in the
  wheel, so package data needs no extra configuration.
- Operator chose offline lookup over Nominatim: no egress, deterministic, neighborhood only where the
  data happens to have it.

## Goals / Non-Goals

**Goals:**
- Name a position as neighborhood (when available), city, country with no network and no new
  dependency.
- Keep renderers pure and the reception path free of I/O and heavy CPU.

**Non-Goals:**
- Street-level or address accuracy; administrative regions (county, state).
- Localised names — GeoNames `name` column (local/common name) is used as-is.
- Showing places anywhere but webhooks (web panel, map) — later change can reuse `sighop.geo`.
- Automatic data refresh; the file is regenerated by hand when wanted.

## Decisions

### D1. Data: GeoNames `cities1000` + `countryInfo.txt`, preprocessed and vendored
`scripts/build_places.py` downloads `cities1000.zip` and `countryInfo.txt` from
`download.geonames.org/export/dump/`, keeps feature class `P`, and writes
`src/sighop/geo/places.tsv.gz`: one row per place — kind (`c` city / `s` section), latitude and
longitude rounded to 4 decimals (~11 m), ISO country code, name — sorted by GeoNames id so output
is reproducible. Country names go to `src/sighop/geo/countries.tsv` (code, English name). A header
line records the GeoNames download date. `PPLX` is a section (neighborhood candidate); `PPLH`,
`PPLQ`, `PPLW`, `PPLCH` (historical, abandoned, destroyed, religious centre) are dropped; every other
`PPL*` is a city.

Expected size: ~165k rows, roughly 2–3 MB gzipped. Committed to the repo.

*Alternatives:* `cities500` (more villages, ~2× size — marginal gain); `cities5000`/`15000` (small but
poor rural coverage and few sections); `reverse_geocoder` PyPI package (pulls numpy/scipy, no musl
wheels guaranteed, no neighborhoods); downloading at image build (network at build time, tests need
it anyway, non-reproducible). OSM admin boundaries would give true containment but are hundreds of MB.

### D2. Lookup: nearest-point search over a 1° grid
`sighop.geo.Gazetteer` holds cities and sections in two columnar stores (`array('d')` latitudes and
longitudes, parallel list of names and country codes) each indexed by a `dict[(floor(lat),
floor(lon))] -> array('I')` of row indexes. A query scans the cells within the search radius
(lat span `ceil(r/111.2 km)`, lon span widened by `1/cos(lat)` at the band's highest latitude, capped
at the full circle, longitude wrapped modulo 360), computes haversine distance, and keeps the
nearest; ties keep the lower row index (stable order ⇒ deterministic).

- City: nearest `c` row within **50 km**, else no place.
- Neighborhood: nearest `s` row within **3 km**, dropped if its name equals the city's
  (case-insensitive).
- Country: city's code → `countries.tsv` name; unknown code → the code itself.

"Nearest town" rather than containment means a suburb that is its own GeoNames place (e.g. Solna)
wins over the big city next door. Accepted: the operator wants a rough location, and it is correct
more often than not.

*Alternative:* KD-tree — faster but more code for no practical gain; grid query is well under 1 ms.

### D3. `Place` and where it is resolved
`sighop.geo.Place(neighborhood: str | None, city: str, country: str, country_code: str)`, frozen.
`WebhookEvent` gains `place: Place | None = None`.

Resolution happens in `WebhookDispatcher.run()` after popping an event and before `dispatch()`:
`event = dataclasses.replace(event, place=await self._places.name(event.position))` when a position
exists. The same resolved event feeds every webhook and every retry. `send_sample()` does the same
before rendering. `on_observation` is untouched, so the reception path does no lookup.

*Alternative:* resolve in `event_from_observation` — would put a first-use file load (hundreds of ms)
and the lookup on the reception path. Rejected.

### D4. `PlaceNamer`: lazy, one load per process, failure contained
`sighop.geo.PlaceNamer` wraps a loader: first `await name(position)` takes an `asyncio.Lock`, loads
the gazetteer with `asyncio.to_thread`, and caches either the gazetteer or the failure. On failure it
logs `place_lookup_unavailable` once (`outcome="error"`) and returns `None` forever after. A lookup
exception on a loaded gazetteer is logged and yields `None` rather than dropping the event.
A module-level default namer is shared by the dispatcher and `send_sample` in a process; tests inject
a fake namer (constructor argument on `WebhookDispatcher`, keyword on `send_sample`).

### D5. Rendering
- JSON: `node.position.place = {"neighborhood", "city", "country", "country_code"}` or `null`.
  Additive under schema 1.
- Discord: `discord_location(position, place)` returns `"<place line>\n[lat, lon](url)"`; place line
  is `", ".join` of neighborhood (if any), city, country, passed through `escape_discord` (data is ours
  but names contain `-`, `(`, `'`; escaping keeps masked-link syntax safe). No place → current output.
- Field stays inline; values are far below Discord's 1024-character field limit.

### D6. Attribution
README gains a short "Data" note: place names © GeoNames (geonames.org), CC BY 4.0. The generated
data file's header repeats it.

## Risks / Trade-offs

- [Nearest point ≠ containing city; border towns can name the neighbouring country's town] →
  Accepted as "rough"; 50 km cap limits nonsense at sea.
- [Sparse regions (northern Scandinavia, deserts) may have no town within 50 km] → Position shown
  without place, as today.
- [Neighborhood coverage is uneven — GeoNames has `PPLX` rows mainly for large cities] → Neighborhood
  is optional in both formats.
- [~2–3 MB binary in git, grows on each refresh] → Refresh rarely; single file replaced wholesale.
- [~28 MB extra resident memory once loaded (measured; ~1 s load on a dev machine)] → Loaded only when the first positioned event is
  dispatched; processes without webhooks never load it.
- [GeoNames names may contain markdown-significant characters] → Escaped in Discord.

## Migration Plan

No database or config change. Deploy the new image; existing webhooks gain the place automatically.
JSON consumers see one additive field. Rollback: previous image.

## Open Questions

- Exact committed file size is known only after first generation; if it exceeds ~5 MB, drop
  coordinates to 3 decimals or switch to `lzma` before committing.
