The key is generated in this process and sealed straight into the store — the two steps sighop keys new and sighop keys import take, with no keyfile in between. To bring in an identity you already hold rather than generating one, give its private key below; a supplied key is checked against the same node hash rules, which it cannot be rolled past, so a reserved or already-taken hash is refused rather than worked around.

A bot adverts as a chat node, indistinguishable from a companion; only the stored role tells them apart, and it is set here rather than inferred.

To bring in an identity you already hold — the 64-byte private key a MeshCore device stores, as 128 hex characters. Its public key and node hash are derived from it, so the identity arrives here as the same one it is elsewhere and no peer has to re-add it. A 32-byte seed is not accepted. Leave this empty and a new key is generated. This field is not filled back in if the form is refused, because a private key does not belong in a re-rendered page.

exporting an identity

An exported keyfile is an unencrypted private key protected only by its file permissions. That is different protection from the entity store's, where the key is sealed under SIGHOP_SECRET_KEY and a database dump alone does not yield it.
